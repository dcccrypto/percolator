# Resolved close: Aristotle results (run 1)

**Read [../ours2/README.md](../ours2/README.md) first.** Run 2 works on the engine's own text for this path; this folder is the record of run 1 and is not changed apart from this note.

Run 1: seven properties (RC1–RC7) were proved on Harmonic's Aristotle about a Rust **hand transcription** of the close path, not about the engine source; none were refuted. The run took about 87 minutes and assumed the `wide_mul_div_floor_u128` contract. Kani covers the same path for one or two accounts with bounded amounts.

What run 1 does and does not say about the engine (details in [SLICE-DIFF.md](SLICE-DIFF.md) and in run 2):

- Only `wide_math.rs` and the rate/claimable/receipt-payment helpers are the engine's own text, byte for byte; RC1 is about those. The three functions that move the payout (`create_resolved_payout_receipt_if_needed`, the close tail, the top-up) are rewritten over plain structs, with the engine's account views, byte decoding, the receipt-clearing call `clear_fully_diluted_resolved_receipt_if_terminal`, the snapshot initialisation, the validation calls and everything before the close tail removed. RC2–RC7 are about that transcription.
- Nothing here shows the engine always reaches the close in a state that satisfies the invariant.
- The transcription left out the engine's `clear_fully_diluted_resolved_receipt_if_terminal`. With that function present (run 2's slice), run 1's invariant is **not** kept by a close, and run 1's RC6 ("the same accounts for any order") is **false**: both are shown by running the engine text (`../ours2/check/`, example in `../ours2/project/aristotle/resolved_close_spec.md`). So RC2's conclusion "`Inv` holds after" and RC6 do not carry over to the engine word for word; RC4, RC5 and RC7 are built on the same `Inv`. Run 2 restates all of them with a list of cleared receipts.
- RC3 (no `Err`) does not carry over to the engine (the transcription dropped engine checks that can fail).

Details, credits, timing and caveats of run 1 are in [JOB.md](JOB.md). The Lean statements Aristotle returned are in [result/](result/).

# How the job was prepared

This section is the original preparation note. The results of the run are at the top of this file and in [JOB.md](JOB.md).

Why this path and not the trade or the full refresh:

1. What bounded model checking cannot reach here is exactly "any number of accounts, any order",
   and the property is arithmetic over a list. Upstream's Aristotle record (aeyakovenko/percolator
   `proofs/README_SECTION.md`) is: arithmetic and pure kernels proved, the trade pilot 1 of 21, the
   small entry points 2 of 11, "The cost was the byte-level model of the 9,419-byte account".
2. The value-moving code of the close is small and nearly pure: three functions of `src/v16.rs`
   on plain values (rate, claimable, receipt payment) plus about 50 lines of the entry point.
   It can be cut out without the account views; the trade and the refresh cannot.
3. A failure is concrete and silent: `close_resolved_account_not_atomic` pays
   `min(capital + claim, vault)` and then zeroes the account's capital whatever was paid
   (`src/v16.rs:26656-26688`). If the claims could exceed the pool, late closers would lose capital.

## What Aristotle takes

`aristotle submit --help` (aristotlelib 3.4.0): "`--project-dir PROJECT_DIR` The folder of Verilog,
C, or Rust code to verify." Its documentation says a project with only Lean files verifies nothing
and that Aristotle writes the Lean itself. So the job is the Rust crate and the property in
English; the Lean files here are for a reader to check what was meant, and to compare with the
statements Aristotle writes.

## Checks made (2026-11-21)

- `python3 gen_slice.py --check`: both generated files identical to the engine's code.
- `rustc --edition 2021 --crate-type lib --emit=metadata -C overflow-checks=on project/src/lib.rs`:
  no error, no warning. (Not built with cargo, not run, not tested.)
- Lean 4.34.0 (`statements/lean-toolchain`), core only: `ResolvedCloseModel.lean` compiles;
  `ResolvedClose.lean` compiles with 7 `declaration uses sorry` warnings.
- `python3 check_statements.py 60000`: no counterexample in 5 parameter sets (about 30,000
  invariant states each). This is a mirror of the model in Python, so it proves nothing.
- `aristotle submit --dry-run`: "would upload 6 files (21.3 KB)", listed below.
- `aristotle submit` without a key: exit 5, "Aristotle API key not found."

Not checked: that `close_path.rs` behaves as the engine's entry points do (it is a transcription
by hand); that the Lean model matches the Rust slice (also by hand); that the engine reaches the
payout tail only in a state satisfying `Inv`.
